# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in this repository, please report it by emailing:

**`security@graph-engineering-course.example`** *(placeholder — update before publishing to production)*

We ask that you do not publicly disclose the vulnerability until we've had a chance to assess and address it.

### What to include

Please provide:

1. A description of the vulnerability.
2. Steps to reproduce it (if applicable).
3. The potential impact.
4. Any suggested fixes or workarounds.

### Response timeline

We aim to acknowledge your report within 48 hours and provide an initial assessment within 5 business days. We will keep you informed of our progress and notify you once the issue is resolved or if we determine it's not a valid security concern.

## Scope

This is a **documentation and starter-kit repository**. The course itself (markdown files in `docs/`) has no runtime security exposure.

**Vulnerabilities to report:**

- Security flaws in example code or starter kits (under `starters/`).
- Unsafe patterns or missing guardrails documented in the course that could lead to harm if followed.
- Dependency vulnerabilities in the website build (`web/`).
- Other code in `scripts/` that processes or validates course content.

**Out of scope:**

- Typos or clarity issues in the course (report as a regular issue instead).
- Requests for features or pattern additions.
- Attacks against the community or maintainers.

## Responsible disclosure

We appreciate researchers and developers who responsibly report security issues. We will credit you (if you wish) in our security advisory and in `resources/sources.md`.

Thank you for helping keep Graph Engineering safe.
